# Public functions without a performance case

Read by `refbench` in its CI mode (`cd bench && go test -run TestPerf .`). Every public function of the module either has a case in `bench/perf_test.go` or is named here with its reason. The cases cover the two paths whose speed users feel: the sector path (`Container.WriteAt`, `Container.ReadAt`) and the password KDF (`PasswordFactor`).

- `Create`: Argon2id (the `PasswordFactor` case), then one pass of ChaCha20 filler over the file, then the slot seals. There is no C program that formats a Theca container to compare against.
- `Open`: Argon2id (the `PasswordFactor` case) plus 16 slot trial-opens of 2 KiB each. No C counterpart.
- `Container.Verify`: one `Sector/Open` per written sector plus the tree walk. Its per-sector cost is the `Sector/Open` row.
- `Container.Sync`: the journal commit, i.e. sealed records, four flushes and a header seal. It is bounded by the backing's flush latency, not by computation, and there is no C counterpart.
- `DefaultJournal`: one clamp of an integer, once per `Create`.
- `Resize`: a one-off offline copy, run by hand: two opens (Argon2id, measured elsewhere), then a few sequential passes (hash through the source, raw copy, verify and hash through the copy); its per-sector cost is the `Sector/Open` row and the copy is bounded by the backing's sequential read and write.
- `Container.Close`: `Sync`, then the keys are wiped.
- `Container.AddSlot`: one slot seal (2 KiB, TA1) and a commit. Rare and interactive.
- `Container.RemoveSlot`: one 2 KiB random write and a commit. Rare and interactive.
- `Container.EnrollFIDO2`: dominated by the user's touch on the key.
- `Container.Info`: a copy of a small struct.
- `Container.Size`: a multiplication.
- `RecoveryFactor`: parses 33 characters and runs one HKDF. No KDF cost by design (160 bits of entropy).
- `FIDO2Factor`: one HKDF.
- `Factor.Zeroize`: clears 32 bytes.
- `FileBacking.Size`: one `fstat`.
- `Container.RemoveFactors`: derives the factors given (the `PasswordFactor` case for a password), trial-opens the slots (16 of 2 KiB) and rewrites the removed ones with one commit. Rare and interactive. No C counterpart.
- `Container.RemoveFactorSets`: `RemoveFactors` for several factor sets at once (a key paired with a partner is one set per credential): the same 16 trial-opens per set and one commit. Rare and interactive. No C counterpart.
- `KeyPairs`: one `Derive` (the user's touch on the key) and one HKDF per credential and partner.
- `WipeSets`: clears 32 bytes per factor.
- `Container.Slots`: trial-opens up to 16 slots of 2 KiB each, one TA1 open per slot (the `Sector/Open` row per byte). No C counterpart.
- `Container.SlotsOf`: the same trial-opens as `Slots`, for a given factor set.
- `fido2.Device.Close`: releases a USB HID handle.
- `fido2.Device.Derive`: dominated by the USB round trip and the user's touch on the key, in milliseconds to seconds.
- `fido2.Device.Enroll`: dominated by the user's touch on the key.
- `fido2.Open`: enumerates and opens a HID device. Operating-system I/O.
- `share.CheckAddr`: parses a listen address and refuses a non-loopback one without `--network`. A few string operations.
- `share.Format`: lays an exFAT file system onto an empty volume, once at creation. Its cost is the sector writes (the `Sector/Seal` row) plus a few metadata structures. No C program formats a Theca volume.
- `share.Share.Addr`: returns a stored string.
- `share.Share.Done`: returns a channel.
- `share.Share.Err`: returns a stored error.
- `share.Share.MountPath`: returns a stored string.
- `share.Share.Password`: returns a stored string.
- `share.Share.Stop`: closes the listener and unmounts. Bounded by the operating system.
- `share.Share.URL`: formats a URL from stored fields.
- `share.Share.User`: returns a stored string.
- `share.Start`: opens the listener and, with `--mount`, asks the file manager to mount the share. Bounded by the network stack and the file manager. The served path is `Container.ReadAt` and `Container.WriteAt`.
- `tpmcounter.Create`: opens the TPM and runs `NV_DefineSpace` plus a few `NV_ReadPublic` probes, once per container. Bounded by the TPM (tens of milliseconds); there is no C counterpart.
- `tpmcounter.Open`: opens the TPM and runs one `NV_ReadPublic`, once per mount. Bounded by the TPM.
- `tpmcounter.Counter.Read`: one TPM `NV_Read`. Bounded by the TPM.
- `tpmcounter.Counter.Increment`: one TPM `NV_Increment` (an NV write) and one `NV_ReadPublic`, once or twice per mount. Bounded by the TPM's NV write latency.
- `tpmcounter.Counter.Destroy`: one `NV_UndefineSpace`, only to undo a failed create.
- `tpmcounter.Counter.Handle`: returns a stored integer.
- `tpmcounter.Counter.Name`: returns a stored slice.
- `fido2.WithNotice`: stores one function pointer in an option.
- `fido2.WithDevice`: stores one string in an option.
- `fido2.Device.Label`: returns a stored string.
- `tpmcounter.Counter.Identity`: one `TPM2_CreatePrimary` of the ECC P-256 EK plus one `TPM2_FlushContext`, once per mount. Bounded by the TPM's key derivation; there is no C counterpart. Measured on swtpm, 1-minute load 13 (so the time is indicative, the two command count is exact): 0.26 ms against 0.04 ms for `Read` and 0.33 ms for `Increment`. A hardware TPM was not measured.
- `ShortID`: hex of at most six bytes, for a message.
- `profile.DefaultPath`: one `os.UserConfigDir` and a join, once per command.
- `profile.ValidName`: a scan of at most 64 bytes.
- `profile.New`: fills a struct.
- `profile.Profile.UsesKey`: a boolean test.
- `profile.Profile.Validate`: a handful of string checks on a few dozen bytes, once per command.
- `profile.Parse`: the profile file is at most 1 MiB and in practice a few hundred bytes; read once per command.
- `profile.Marshal`: the same file written once per `profile add` or `remove`.
- `profile.Store.Load`: one file read and a `Parse`. Operating-system I/O, interactive.
- `profile.Store.Save`: an atomic replace of the file. Operating-system I/O, interactive.
- `profile.Store.Get`: a `Load`.
- `profile.Store.Add`: a `Load` and a `Save`.
- `profile.Store.Remove`: a `Load` and a `Save`.
- `profile.Store.List`: a `Load` and a sort of at most 256 names.
- `session.SocketPath`: a path join and length check.
- `session.DecodeRequest`: one line of at most 4096 bytes on a local socket, once per `close` or `status`.
- `session.DecodeResponse`: one line of at most 4096 bytes, once per `open`, `close` or `status`.
- `session.Report`: writes one line of at most 4096 bytes.
- `session.Listen`: creates one Unix socket, once per `open`.
- `session.Server.Serve`: accepts the connections a person starts with `close` and `status`.
- `session.Server.Shutdown`: closes the listener and removes the socket file.
- `session.Status`: one Unix-socket round trip of two short lines.
- `session.Close`: one Unix-socket round trip; it waits for the unmount and the commit, which are `share.Share.Stop` and `Container.Sync`.
- `session.Start`: starts one process, once per `open`; it waits for the unlock (a Argon2id derivation and a key touch, measured elsewhere).
- `session.StartAttached`: the same, with the terminal's streams.
